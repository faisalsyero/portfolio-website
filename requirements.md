Band 1 – Pass Requirements (Core Technical Skills) [Page 7]

1. Semantic HTML

- Use correct HTML5 structural elements (<header>, <main>, <section>, <footer>).

- Each page contains a single <h1> for the main heading.

- Use <h2>, <h3>, etc., to reflect page structure.

- Use semantic wrappers around major content areas.

- Fail if:

- Multiple <h1> tags per page.

- Missing <main> or other semantic elements.

- Use of non-semantic tags like <div> for main content without purpose.

- Random heading levels (e.g., skipping levels).

2. Three Page Website

- Must include Home, About, Portfolio pages.

- Pages are linked via navigation (consistently present on all pages).

- Files: index.html, about.html, portfolio.html.

- Fail if:

- Missing a page.

- Navigation/link does not work on all pages.

- Placeholder pages with no meaningful content.

3. Responsive Design

- Layout adapts correctly on desktop, tablet, mobile.

- Navigation remains usable on all device sizes.

- Achieved via Bootstrap grid or CSS flexbox.

- Text scales without overflowing.

- Fail if:

- Horizontal scrolling.

- Overlapping or overlapping components.

- Navigation becomes unusable or disappears on mobile.

4. CSS / CSS Library Usage

- Uses CSS or a CSS framework (e.g., Bootstrap).

- Link to external CSS file or CDN.

- Apply consistent styling.

- Use classes instead of inline styles.

- CSS files organized in /css folder.

- Fail if:

- No CSS applied.

- Inline styles only.

- Broken CSS links.

5. Extensible Portfolio Page

- Portfolio items are in a repeatable structure (cards or blocks).

- Use same HTML structure for each item.

- Easy to add more items later.

- Fail if:

- Different layout per item.

- Hardcoded, non-repeatable structures.

- Items are not distinguishable or grouped properly.

6. Basic GitHub Usage

- Code hosted in a GitHub repo.

- Regular meaningful commits (not a single upload).

- Commit history shows development.

- The repo is public.

- Fail if:

- Only one commit, titled "final version."

- Upload as a ZIP file.

- No commit history.

7. Deployment

- Site deployed online (e.g., GitHub Pages).

- Link works without 404 errors.

- Files in correct location (index.html in root).

- Test on mobile and desktop.

- Fix broken paths, filenames, case sensitivity.

- Fail if:

- Site not accessible.

- 404 errors.

- Wrong branch or capitalization errors.

8. Code Quality

- HTML validates with no critical errors.

- Well-structured, organized, and indented.

- Organize files into proper folders (css, images, js).

- Fail if:

- Invalid markup.

- Unclosed tags.

- Files poorly organized or scattered.
